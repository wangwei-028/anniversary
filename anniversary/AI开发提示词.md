# 任务：从零开发网页游戏《奔向你 · 我们的365天》（一周年纪念礼物）

## 背景

我在给女朋友准备一周年纪念礼物，要做一个网页游戏。完整策划书在项目根目录 `游戏策划书.md`（v1.1），**请先完整阅读它，它是唯一需求文档，一切设计、数值、内容以它为准**。本提示词只补充技术约束和工作方式。

## 你的角色

资深 H5/小游戏开发者，独立负责从 0 到可部署上线的全部工作。我不提供任何美术/音频素材：像素风素材全部用代码程序化生成或用占位图；个性化内容（照片、日期、信、梗文案）集中在配置文件里用占位值，并清楚标注，我之后自己替换。

## 技术硬性要求

1. 纯 HTML + CSS + JavaScript（ES Modules）+ Canvas 2D 渲染。**零第三方依赖、零构建步骤**：双击 `index.html` 或任意静态服务器即可运行。
2. **竖屏优先**适配移动端浏览器（viewport、禁页面滚动、防误触缩放），支持触控手势：左右滑变道、上滑跳跃、下滑滑铲、点击反击；同时支持桌面键盘：←→/AD 变道、↑/W/空格 跳、↓/S 滑铲、J 或鼠标点击 反击、Esc 暂停。
3. 存档用 localStorage，数据结构带版本号字段，避免后续改版丢档。
4. 目标 60 FPS：障碍物与弹幕用对象池、避免每帧产生垃圾、静态背景用离屏 Canvas 缓存。
5. 代码模块化、数据驱动，建议结构：
   - `scenes/`：标题、地图选择、关卡准备、局内跑酷、Boss战、结算、回忆放映厅
   - `systems/`：输入、关卡生成器、难度、经济、存档、音频、粒子反馈
   - `data/`：关卡与障碍配置、Boss 弹幕模式配置、商店配置、难度曲线表、文案
   - `config.js`：全部个性化内容
   - `main.js`：入口与场景切换
   关卡障碍、Boss 弹幕模式尽量做成配置数据，不许把数值写死在逻辑代码里。
6. 美术：像素风，16×16 基础单位、整数倍放大、`image-rendering: pixelated` 保证像素锐利；素材用 Canvas 程序化绘制或内嵌精灵图；每张地图独立调色板（配色见策划书第 5 章关卡总览表）。
7. 音频：音效用 Web Audio API 程序化合成（跳跃、滑铲、金币、受击、完美闪避"叮"、还击命中、Boss 登场、胜利等约 15 个）；BGM 用可免费商用（CC0）资源或程序化 chiptune 循环，注意版权，在 README 注明来源。
8. 数值实现以策划书 **第 4.4 节难度递进表** 和 **第 12 章数值附录** 为唯一依据，落成 `data/` 下的数据表。

## 个性化占位（集中在 config.js，方便我最后替换）

- `anniversaryDate`：在一起的日期，默认 `2025-10-01`，标题画面"今天是和 TA 在一起的第 N 天"要用它实时计算；
- `photos`：21 张照片（每关 3 张）+ 各配一句话，照片先用 picsum 占位图；
- `letter`：隐藏结局《回忆放映厅》最后那封信，先放示例文本；
- `memes`：结算页"恋爱冷知识"、招牌名等梗文案数组。
- 所有占位处写 `// TODO: 替换为真实内容` 注释，并在 README 里列出替换清单。

## 开发流程（严格遵守里程碑，禁止一次做完）

按策划书第 11 章的 M1→M4 顺序，**本次对话只做 M1**：

- M1 范围：第 1 关「商场」+ Boss 喵喵完整可玩（三阶段弹幕 + 登场演出含 Boss 名条与 LOVE FEVER + 反弹还击 + 完美闪避判定）、金币/拾取物、1 心生命、Boss 战 2 次重开机制（失败金币不损失、从 Boss 战开头重开，第 3 次失败即本关失败）、最简 UI（标题 / 单关选择 / 结算）、桌面+手机双端操作、主角为女孩像素小人（策划书第 13 章已定案：默认主角为女孩，竖屏优先）。
- M1 手感验收标准（game juice 必须做，这是能不能"好玩"的命根）：输入缓冲、跳跃郊狼时间、受击顿帧与无敌闪烁、完美闪避触发 0.3s 子弹时间、金币收集飞向计数器、镜头轻微震动与速度感（地面条纹/视差背景加速）、落地粒子。
- 完成 M1 后**停下来**：自测完整流程，给我（1）运行/测试方法（2）一份试玩反馈点清单（手感、难度、操作哪里别扭），等我确认后再进 M2。

## 工作方式要求

1. 策划书未覆盖的实现细节，自行做合理决定，在 README 的「开发决策记录」小节写一行说明即可，**不要中途停下来问我**（个性化内容除外，一律占位）。
2. 分小步实现，每一步完成后游戏都必须处于可运行状态，绝不交付跑不起来的中间状态。
3. 全中文注释、全中文 UI 文案；代码可读可维护，不压缩、不省略。
4. 每个里程碑结束时更新 README：怎么运行、当前进度、下一步计划、占位内容替换清单。

现在开始：先用不超过 10 行复述你对 M1 范围的理解，然后直接开始实现。
